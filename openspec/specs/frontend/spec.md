## 1. Application Structure

```
AppComponent (root — always visible)
│  mat-toolbar ("Student Housing" brand + AppNavMenuComponent)
│  router-outlet
│
├── /home              → HomeComponent (public)
├── /login             → LoginComponent (public)
├── /signup            → SignupComponent (public)
├── /verify-email, /forgot-password, /reset-password (public)
├── /profile-setup, /application-submission, /document-upload,
│   /application-review, /application-confirmation  (AuthGuard + StudentGuard)
│
├── /dashboard, /applications, /applications/new,
│   /applications/:id, /documents, /profile,
│   /contact-support              (AuthGuard + StudentGuard + EmailVerifiedGuard)
│
└── /admin             → AdminLayoutComponent
       └── AdminSidebarComponent (sidenav shell, 250px fixed)
              router-outlet (children load here)
```

**Two navigation shells coexist:**
- Students: `AppComponent` toolbar (top) + hamburger menu + desktop nav tabs
- Admin: `AppComponent` toolbar (still present, double chrome) + `AdminSidebarComponent` (side)

## 2. Design System — What Exists

```

  Module accents (color-coded per feature):
    Purple:       admin dashboard, users, allocations, institutions
    Blue:         applications, documents
    Cyan:         rooms
    Orange:       buildings
    Green:        year-of-study
    Gray:         activity logs, settings

TYPOGRAPHY
  Font:          Inter (+ system stack fallback)
  Scale:         h1 32px/700, h2 22px/700, title 20px/700,

                 small 13px, tiny 12px, badge 11px/600

SPACING     $space-1 (4px) … $space-12 (48px)
RADII       sm 6 / md 10 / lg 20 / xl 24 / pill 9999px
```

## 3. UX Pattern Inventory

### 3.1 Navigation Patterns

**Student nav (top bar):**
```
┌─────────────────────────────────────────────────────────────┐
│ 🏠 Student Housing          [🔔] [≡ menu]  Dashboard  Apps  │
│                                              Documents  Profile▼│
└─────────────────────────────────────────────────────────────┘
  ↑ Always-visible mat-toolbar with hamburger (mobile) and desktop tabs
```

**Admin nav (dual chrome):**
```
┌─────────────────────────────────────────────────────────────┐
│ 🏠 Student Housing                      [🔔] [≡ menu]       │
└─────────────────────────────────────────────────────────────┘
┌──────────┬──────────────────────────────────────────────────┐
│Admin     │                                                   │
│Portal    │     <admin page content>                         │
│──────────│                                                   │
│Dashboard │                                                   │
│Applications│                                                 │
│Documents │                                                   │
│Buildings │                                                   │
│  ...     │                                                   │
└──────────┴──────────────────────────────────────────────────┘
  ↑ 250px sidebar + top toolbar BOTH present simultaneously
```

**Problem:** Top toolbar always renders, even in admin context. Admin gets double nav chrome. The toolbar's "Student Housing" brand + hamburger menu is irrelevant for admins.

### 3.2 Page Layout Pattern (Admin pages)

```
.{page}-container              (padding 1–2rem, max-w 1600px, margin-top 64px)
  .page-header
    h1 [mat-icon] Page Title
    p.subtitle
  [filter card / action bar]
  [data table card]
```

`margin-top: 64px` is a hardcoded offset to clear the top toolbar — fragile, breaks if toolbar height changes.

### 3.3 Table Pattern

Every admin data page implements **two views manually**:
```
.mobile-cards-container   (visible < tablet)
  .mobile-card
    .mobile-card-header
    .mobile-info-grid
    .mobile-actions

.table-container           (hidden < tablet via CSS display:none or similar)
  table[mat-table]
  mat-paginator
```

This is duplicated in: application-review, room-allocation, admin-dashboard occupancy, document-verification, building-management, etc. No shared responsive table component.

### 3.4 Form Pattern (Filter + Data Entry)

Filter cards:
- `mat-form-field appearance="outline"` — consistent
- `mat-card.filter-card` > `.filter-form` > fields + `.filter-actions`

Auth forms (login/signup):
- Centered card on full-page background
- `mat-card.login-card` > form fields

Multi-step wizard (application submission — 4 step stepper):
- Uses `mat-stepper` with custom step components

### 3.5 Empty / Loading / Error States

| Pattern | Implementation |
|---------|---------------|
| Loading spinner | `mat-spinner` inline — inconsistent sizing (48px admin, 40px in cards) |
| Empty state | Mix of inline `<div class="no-data">` + `EmptyStateComponent` — **not unified** |
| Error state | `ErrorDisplayComponent` used in some admin pages, not all |
| Skeleton | `SkeletonLoaderComponent` exists but almost never used |

## 4. Issues & Inconsistencies

### 4.1 Critical — Navigation & Layout

1. **Double chrome for admins**: Top toolbar always present. Admin layout adds sidebar on top. The `mat-toolbar` is in `AppComponent` which wraps everything.
2. **`margin-top: 64px` hardcoded** in all admin pages — brittle, duplicated across 15+ component SCSS files.
3. **No brand logo/icon** — just text "Student Housing" in toolbar, "Admin Portal" text in sidebar header.
4. **Sidebar has no visual identity** — plain white, 250px, minimal styling. No gradient header, no logo.

### 4.2 Design Inconsistencies

5. **Color theme split**: Home page uses slate-900/cyan dark gradient. Student dashboard uses the same. Admin dashboard uses purple. Application review uses cyan for h1 icon. Admin sidebar active state is purple. No single "primary" color — the Material theme `color="primary"` maps to something different from the module-accent colors.
6. **Inline hardcoded hex colors in templates**: `style="color: #f59e0b"` and `style="margin-top: 10px; display: flex..."` in `dashboard.component.html` — bypassing the design token system.
7. **`status-warning` CSS class missing** from `ModernStatusBadge` inline styles — `under_review` maps to `status-warning` but that class isn't defined in the component's styles (it's defined in `styles.scss` global). Component styles are `ViewEncapsulation.Emulated`, so global styles may not penetrate.
8. **Deprecated SCSS**: `darken()` function used in `admin-dashboard.component.scss:618` — causes build warnings.
9. **`mat-icon` font-family fix repeated**: 3+ component SCSS files declare `mat-icon { font-family: 'Material Icons' !important; }`. Should be global once.
10. **`global_styles.css` not migrated**: TODO comment in `styles.scss`. Legacy CSS includes Tabler icon import (CDN), commented-out root variables, and stale patterns.

### 4.3 Component & Template Inconsistencies

11. **Old directive syntax in sidebar**: `admin-sidebar.component.html` uses `*ngFor="let item of navItems"` (structural directive) while all other templates use `@for` control flow. The sidebar also uses `*ngIf`.
12. **`EmptyStateComponent` not consistently used**: Admin pages have inline "no data" divs. Some use `EmptyStateComponent`, others write `<div class="no-data"><mat-icon>inbox</mat-icon><p>No X found</p></div>`.
13. **`SkeletonLoaderComponent` unused in admin**: Only student pages potentially use it. Admin pages show `mat-spinner`.
14. **`ErrorDisplayComponent` partial adoption**: Used in application-review but not other admin pages.
15. **Duplicate mobile/desktop logic**: Every admin list page has two full implementations (mobile cards + desktop table). This is ~40% code redundancy per page.

### 4.4 Missing Patterns

16. **No breadcrumbs**: Admin has 15+ nested routes. No contextual navigation trail.
17. **No page action bar pattern**: Some pages put actions in the filter card, some in the page header — inconsistent.
18. **No loading skeleton for admin**: The skeleton component exists but admin uses spinners only.
19. **No notification center page**: Only a bell component — clicking it shows a dropdown but there's no dedicated `/notifications` route.
20. **`/settings` route missing**: `AppNavMenuComponent` links to `/settings` for students but that route doesn't exist in `app-routing.module.ts`.
21. **Feature flags UI**: Spec exists (`openspec/specs/feature-flags-ui/spec.md`) but no route or component in the frontend.

## 6. What's Working Well

- **Design token system** is solid: `_variables.scss` is comprehensive and properly used via `@use` in most components.
- **`ModernStatusBadge`** is a well-built, reusable, signal-based component covering all domain statuses.
- **`EmptyStateComponent`** is a clean pattern when used.
- **`ErrorDisplayComponent`** supports multiple modes — good architecture.
- **Routing** is fully lazy-loaded with proper guards — no eager loading issues.
- **Admin dashboard charts** are custom CSS donut charts — lightweight, no chart library dependency.
- **Mobile-first responsive** patterns in student area are decent.
- **Inter font** loading is correct; typography scale is defined.
- **Angular 21 standalone components** throughout — no NgModule overhead.
- **`@if` / `@for` control flow** used in most templates (modern Angular syntax).

## 7. Redesign Scope Recommendations

### Priority 1 — Navigation Architecture (High Impact)
- Remove double chrome: Admin should have its own root layout without the student toolbar.
- The `AppComponent` toolbar should only render for non-admin routes (or not at all — move to feature layouts).
- Add brand identity: logo/icon in toolbar and sidebar.
- Improve sidebar: accent-colored header, logo, better active state (left border indicator).

### Priority 2 — Design Consistency
- Fix hardcoded hex colors — move to token system.
- Resolve `status-warning` CSS class gap in `ModernStatusBadge`.
- Standardize h1/h2 sizes using mixins instead of per-component overrides.
- Fix deprecated `darken()` SCSS.
- Migrate admin-sidebar to `@for`/`@if` control flow.

### Priority 3 — Shared Component Unification
- Replace all inline "no-data" divs with `EmptyStateComponent`.
- Add skeleton loading to admin pages.
- Create a reusable `DataTableComponent` that handles mobile card / desktop table pattern.

### Priority 4 — Missing Features
- Add feature flags route/component (spec exists).
- Fix broken `/settings` route.
- Add breadcrumbs to admin routes.

### Priority 5 — SCSS Cleanup
- Migrate `global_styles.css` content into `styles.scss` or modules.
- Remove duplicate `mat-icon` font-family fixes.
- Replace `darken()` with `color.scale()`.
